# Notes page implementation

## Layout

- `app/src/notes.rs` holds `GET /projects` and `POST /notes-assign`. `GET /projects` gives the id and the name of each project in `conf/projects.json`. `POST /notes-assign` takes `tab` and `text`. It finds the project path with `project_root`, makes the prompt with `task_prompt`, and calls `start_agent` of `app/src/open_behaviour.rs`. It returns `{"chat": "<chat id>"}`. An empty text or an unknown project returns 400.
- `start_agent` makes the chat id `local-<nanoseconds since 1970>` and creates `app/data/resolve/<chat id>.log`. It writes `app/data/resolve/<chat id>.prompt` with the prompt and `app/data/resolve/<chat id>.root` with the project path. Then `spawn_local` starts the first agent with the model `claude-sonnet-5-5-medium`. The route does not wait for the agent. When the first agent cannot start, the log gets the error text, and `start_local` starts the Grok agent. When the Grok agent also cannot start, the route returns 500 with the error of the first agent. The server calls no Cursor API.
- `spawn_local` starts `cursor-agent --print --output-format stream-json --force --trust --model <model> --workspace <project path>` with the prompt, in a new process group. The output of the agent goes to the log, and an `exit` line follows when the process ends.
- The two agents share one log. `GROK_START` in the log begins the Grok agent. `last_run` gives the lines of the log after the last `followup` event or `GROK_START` line, or all lines when the log has neither. The end checks read only these lines.
- After the first agent exits, `start_grok_after_fail` runs. When the log has no `followup` event and `local_failed` finds a failed run, it calls `start_local` for the Grok agent. `local_failed` reads the first end of the run: a failed `result` event, or an `exit` line with a code that is not 0 before a `result` event. When the Grok agent cannot start, the log gets a failed `result` event.
- `start_local` holds a lock, writes `GROK_START`, and calls `spawn_local` with the `.prompt` file, the path in the `.root` file, and the model `grok-4.7-high`. The lock and the start line let only one Grok agent start. A missing `.prompt` file or `.root` file, or a failed start, is a failed start. A failed start writes the error text.
- `app/src/open_behaviour.rs` holds `POST /open-behaviour-followup`. The body has `chat` and `text`. A bad chat id, an empty text, a chat with no log, or a last run with no end returns 400. `followup_local` holds the local lock. `local_session` reads the last `session_id` after `GROK_START`, or in the full log when the Grok agent did not start. The route writes the `followup` event and starts `cursor-agent` with the model of the current agent, the `.root` path, `--resume <session id>`, and the text. A follow-up agent does not start the Grok agent. A failed start writes the error text and a failed `result` event. The route returns the progress of the log.
- `app/src/open_behaviour.rs` holds `GET /open-behaviour-progress`. `read_progress` reads the log of the chat. Each `assistant` event with text gives a `message` step. Each `tool_call` event with subtype `started` gives a `tool` step with the tool name and the first of these args: `command`, `path`, `pattern`, `globPattern`, `query`, `url`. Each `followup` event gives a `reply` step with its text and sets the status to `running`. Each line that is not JSON gives an `output` step. `GROK_START` also sets the status to `running`. A `result` event gives the status `finished`, or `failed` and an `output` step with the result text when `is_error` is true. An `exit` line with no `result` event before it gives the status `stopped`. For the first agent with no `followup` event, a failed `result` event and an `exit` line with a code that is not 0 keep the status `running`, because the Grok agent starts next. With no `result` event and no `exit` line, the status is `running`.
- `app/web/notes/context.js` holds the projects, the notes, the assigned tasks, the progress, the load, the add, the edit, the delete, the assign, the follow-up, and the progress load. It has no DOM code. `state.assigns` maps `<tab id>/<note id>` to `"starting"` or to the chat id. `"starting"` is not in the DB. `state.progress` maps an assign key to the last loaded progress. `refreshProgress` loads the progress of each assigned task that is not `starting` and whose status is not `finished`, `failed`, `stopped`, or `error`. A failed load gives the status `error` with the error text. When a loaded progress has the status `failed`, `refreshProgress` saves the assigned tasks without that key, and keeps the progress. If that save fails, the assigned task stays and the page shows the error. `assign` removes the old progress of the key, so the progress of the new agent loads. One `refreshProgress` runs at a time. `followup` sends the text of a started task and keeps the returned progress. A failed send sets the error and keeps the progress. After each change, it calls the `onChange` function of the page.
- `app/web/notes/index.js` builds the page with the DOM API. It builds the cards again only when the selected tab, a note id, or a note text changes. Thus, the follow-up text stays. After the load and each 3 seconds, the page calls `refreshProgress`. A card builds its progress steps again only when the status or the number of steps changes. Thus, the scroll of the steps stays when nothing changes. The card text gives the chat id and tells that the local agent works in the project folder. The follow-up form is in the progress block, after the steps. The page shows it only for a started task with the status `finished` or `stopped`. The input clears after a successful send.
- `app/web/notes/index.css` holds the styles of the page.
- The tests are in `app/src/test/notes.rs`, `app/src/test/open_behaviour.rs`, and `app/web/test/notes/context.test.js`.

## Persist

- The notes are the page data `notes` in table `page`. The assigned tasks are the page data `notes-assigns`. Refer to `spec/app/01_server/code-impl.md`.
- The progress is not in the DB.

## Do not

- Do not write a project name in `app/web/`.
- Do not change the id of a note, also when the user edits the text. The saved task uses it in its key.
